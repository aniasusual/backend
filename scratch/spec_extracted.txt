1. Executive Summary & Core Index
Modern LLM architectures possess context windows scaling up to hundreds of thousands of tokens. However,
direct code deployment without optimization exposes extreme vulnerabilities: needle-in-a-haystack structural
decay, repetition degradation, attention dispersion, and unviable operational spending patterns. This
specification formalizes the architecture required to govern coding context safely without hitting limits or losing
tracking precision.

2. Detailed Technical Breakdown
[CP-101] The Three-Tier Memory Hierarchy
Context layout optimization maps directly to computer hardware design philosophies, defining three volatile
buckets:
1. Static Layer (The ROM/Hard Drive): Positioned permanently at the entry index of the context chain. This file
maps the system profile, repository formatting schemas, coding constraints, and global targets. It is
non-evictable and targets a capacity profile below 1,500 tokens.
2. Dynamic Layer (The Virtual RAM): The volatile buffer managed sequentially via programmatic insertions.
Files and AST subtrees explicitly loaded by tool-calling events map here. This architecture forces modules in
and out via discrete mounting and unmounting procedures.
3. Ephemeral Layer (The L1/L2 Cache): The conversational history, prompt queries, system execution
warnings, and raw tool output packets. This layer handles the highest volatility and triggers rolling truncation
rules automatically.

[CP-102] JIT Context Acquisition & Tool Engines
To avoid performance degradation, systems must implement the ReAct Inversion Principle. The core
orchestrator does not pre-load file blocks on system start. Instead, it exports concrete context acquisition
definitions to the model payload, allowing the agent to parse targets dynamically:
• locate_files_by_pattern: Resolves repository topology into a minimized file name listing to eliminate broad
traversal loops.
• search_grep: Implements high-performance regex or textual lookups, returning exact line offsets and
single-line syntax previews.
• read_file_range: Restricts structural intake by parsing target boundaries via start and end line parameters,
hard-capping single loads to 200 lines.
[CP-103] Active Compaction & Lifecycle Pruning
Standard execution routines (such as runtime compilation and test iterations) create catastrophic token
expansions due to heavy compiler outputs. The context engine runs background data manipulation passes:
• Stdout Processing: Tool responses exceeding a threshold of 2,000 tokens are intercepted. The middle lines
are truncated, preserving the first 30 lines and final 30 lines to retain compiler initializations and stack traces.
• Milestone Roll-ups: Once a sub-goal validates successfully (e.g., tests pass), intermediate diagnostic
conversation iterations are purged and summarized into a single structural success state marker.

[CP-104] Context Isolation via Sub-Agents
Heavy operations (such as analyzing cross-repository interface dependency charts) risk overloading the agent's
core context. The engine triggers a Fork-Join execution sequence. A short-lived sub-agent is initialized with an
isolated, single-use context allocation. This specialized engine performs deep file processing, produces a
concise analysis artifact, and terminates. The orchestrator records only this brief artifact, leaving its core history
unpolluted.
[CP-105] Code Mapping via AST Slicing
Conventional vector retrieval methods fail on codebase logic because files lack clear linguistic proximity. A
production context manager relies on Abstract Syntax Trees (AST) using toolsets like tree-sitter. The manager
creates structural code maps, exposing an extract_signatures tool to the agent. This tool strips out deep interior
logic, loop constructs, and inline code bodies, returning only class interfaces, signatures, and docstrings. This
preserves structural clarity while cutting token volume by up to 90%.

def _calculate_current_payload_size(self) -> int:
tokens = len(self.encoder.encode(self.static_block))
for path, body in self.mounted_virtual_ram.items():
tokens += len(self.encoder.encode(f"FILE: {path}\n{body}"))
for msg in self.ephemeral_history:

return tokens
